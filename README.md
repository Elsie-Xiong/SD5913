# Assignment 1: Why Are We Here?
## Reflection
During my studies in Digital Media Art, I have always been more used to thinking from a designer’s perspective. Rather than focusing on code itself, I was more concerned about what problem a project was trying to solve, what users would experience, and how visuals, space, and interaction could work together to create an experience. Therefore, for a long time, I saw programming mainly as a technical tool for realizing design ideas: designers come up with ideas, and programming helps bring them to life.

However, as I participated in more interactive media projects, I gradually realized that design and technology are actually difficult to separate. This is especially true for projects involving real-time interaction, sensors, computer vision, and generative content. Whether an idea can actually work often depends on whether I understand the technical logic behind it. For example, in my graduation project, I used MediaPipe to capture users’ facial information and translate different emotional states into dynamic mandala visuals. I also used gestures to create further interaction with the system.This experience  made me realize that having an idea such as “turning emotion into a visual response” is very different from understanding how that idea can actually work. Without some technical understanding, I might know what kind of experience I want to create, but not what information the system can detect, how that information can be interpreted, or how it can be used to create an interaction. In a project like this, programming is no longer just a tool used at the final stage. It actually influences how I think about and design the entire experience.

This is also an important reason why I now want to learn more about programming.

After entering postgraduate study, I began to pay more attention to HCI (Human-Computer Interaction), Human-Centred Design, and interactive technology. What interests me is not only creating visually interesting work, but also exploring how technology can be used to understand human behaviour, emotions, and needs, and how we can design systems that truly interact with people. If I continue to conduct research in these areas in the future, I may need to build my own interactive prototypes, connect different sensors or AI models, design experiments, and continuously improve the system based on user testing. Therefore, even if I do not become a professional programmer, I still need enough programming skills to quickly turn a research idea into a prototype that can actually be tested.

At the same time, AI has also changed my understanding of what it means to “learn programming.” In the past, I thought learning programming meant memorizing a lot of syntax and writing all the code by myself from beginning to end. But now, AI tools such as Copilot and Codex can already help us generate and modify code. For designers, I think the more important questions are gradually becoming: What do I want to create? How should the system work? How should different functions be connected? And how can I judge whether the results generated by AI actually match my design goals?

Therefore, I believe that the purpose of learning programming today is not to compete with AI to see who can write code better, but to learn how to work with AI and computational systems. Designers still need to understand the basic structure and logic of programming. Otherwise, even if AI can generate code for us, it will be difficult to know what we should ask it to do, or to judge whether the results are correct.

For me, the most important part of this course is that it can help me bridge the gap between “design ideas” and “working systems.” In the future, I hope I will not only be a designer who proposes concepts, creates interfaces, or produces visual effects, but also someone who can independently turn ideas into prototypes and test them through real interaction and user testing.

So, if I had to answer the question “Why are we here?” in one sentence, my answer would be:
For me, learning programming is not about becoming a programmer, but about gaining the ability to turn my design and research ideas into interactive, testable, and iterative systems.
